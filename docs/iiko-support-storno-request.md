# Обращение в iiko: лицензия на возврат (storno) из плагина

Дата подготовки: 2026-10-12.

## Зачем

Мы хотим из своей админки удалённо возвращать ошибочно пробитый закрытый чек: плагин на кассе
получает команду и вызывает `StornoOrder` / `StornoPastOrder` (iikoFront API V8). Новый чек потом
пробивает кассир. Вызов на тестовой кассе упал на лицензии:

```
LicenseRestrictionException: Method "StornoOrder" isn't licensed
```

Всё остальное в плагине (чтение заказов, события, отметка готовности блюд на кухне) работает.
Сам вход по PIN служебного сотрудника прошёл, права сотрудника в порядке — упёрлось именно в лицензию.

## Что известно, а что нет

Известно (проверено):
- Плагин: `Resto.Front.Api.CustomWebserver`, API V8, SDK 8.7.6032, класс помечен
  `[PluginLicenseModuleId(19011701)]`.
- Касса: iikoFront 9.4.8049 (проверено на тестовой машине).
- Ошибка воспроизводится при реальном вызове `StornoOrder` (заказ текущей смены, оплата HUMO).
- `GetRemovalTypesToStornoPastOrderItems()` отдаёт тип «Без списания» (`WriteoffType.None`),
  `GetPaymentTypesToStornoPastOrderItems()` содержит HUMO — то есть технически всё готово.

Неизвестно (это и надо выяснить у iiko):
- Какие методы входят в лицензию модуля `19011701` и где посмотреть полный перечень.
- Нужен ли для возврата отдельный модуль или тип лицензии («плагин с оплатными операциями»).
  В документации к `StornoOrder` сказано, что плагин должен «поддерживать оплатные операции», но что
  под этим имеется в виду и как оформляется, нигде не описано.
- Лицензирован ли `StornoPastOrder` (возврат из закрытой смены) — не проверяли, нужен отдельный тест.
- Входят ли `UnprocessPayment`, `DeletePrintedOrderItems`, `DeleteOrder`.

## Куда писать

- **api@iiko.ru** — по документации iiko именно сюда подают заявки на регистрацию плагина и лицензируемого
  модуля ([Лицензирование](https://iiko.github.io/front.api.doc/licensing.html)).
- Параллельно — вашему обслуживающему iiko-партнёру (если есть), он может ускорить и знает условия контракта.
- В обращении сразу укажите номер модуля `19011701`, чтобы не гонять письма за уточнением.

Что приложить:
- Текст ошибки (выше) и время/касса, на которой воспроизвели.
- Версии: iikoFront 9.4.8049, API V8 (SDK 8.7.6032).
- Фрагмент лога с ошибкой — **без** номеров заказов, названий филиалов, PIN и токенов.

## Текст письма

**Тема:** Расширение лицензии плагина iikoFront API (модуль 19011701): разрешить StornoOrder и StornoPastOrder

Добрый день!

У нас собственный плагин iikoFront API (Resto.Front.Api V8, SDK 8.7.6032), работает на кассах под
iikoFront 9.4.8049. Идентификатор лицензируемого модуля: 19011701.

Мы хотим добавить в плагин возврат закрытых заказов по команде из нашей административной панели.
При вызове `PluginContext.Operations.StornoOrder(...)` (авторизация через `AuthenticateByPin`,
сотрудник с правом возврата) получаем:

    LicenseRestrictionException: Method "StornoOrder" isn't licensed

Остальные операции плагина (чтение заказов, подписка на события, отметка готовности блюд на кухне)
в рамках этого модуля работают без ошибок.

Вопросы:
1. Какие методы iikoFront API входят в лицензию модуля 19011701 и где можно посмотреть этот перечень?
2. Что нужно, чтобы плагину были доступны `StornoOrder` и `StornoPastOrder`: расширение текущего модуля,
   отдельный модуль, лицензия плагина с оплатными операциями или другое?
3. В документации к `StornoOrder` указано, что плагин должен «поддерживать оплатные операции».
   Что именно имеется в виду и как это оформляется для плагина?
4. Входят ли в тот же набор `UnprocessPayment`, `DeletePrintedOrderItems` и `DeleteOrder`?
5. Стоимость, сроки, нужно ли что-то менять в самом плагине и на каждой кассе (число слотов лицензии,
   версия iikoFront)?

Нам важно понять это до начала разработки. Будем благодарны за ответ и контакт ответственного
по лицензированию плагинов.

С уважением,

1. Если лицензию расширили — повторить реальный возврат на тестовой кассе (текущая смена, затем
   закрытая смена). Проверить гипотезу, что для `StornoPastOrder` нужна открытая смена на кассе.
2. Дальше по плану из `docs/superpowers/specs/2026-10-10-pos-storno-design.md`: очередь команд в managers,
   опрос из плагина, свой токен кассы, защита от повтора.
3. Если iiko откажет — остаётся возврат кассиром на кассе и отчёт по возвратам из iikoServer OLAP
   (поле `Storned`).

## Контекст: чего не получится обойти

- iikoCloud API возврата закрытого заказа не имеет; заказы зала, созданные на кассе, облако не видит.
- iikoServer `resto/api` методов возврата не нашлось.
- Чужой закрытый заказ с другой кассы не виден (`GetPastOrder: Cannot find past order`): возврат должен
  выполнять плагин на кассе своего филиала, команду адресуем по номеру кассы.
- Готового стороннего плагина для удалённого возврата в поиске не нашлось, и у него была бы та же
  лицензионная проверка.
