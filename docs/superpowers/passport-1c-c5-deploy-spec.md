## 1. Жёсткое ограничение: тот же origin

Мини-апп ходит **относительными** путями `/api/passport/tg/*` (`src/api.ts:17`), хоста в коде нет
вообще, а `base` у vite — `/passport-app/` (`vite.config.ts:24`). API живёт на
`api.office.lesailes.uz` → `upstream les_office_api_upstream` → `127.0.0.1:6761`
(`/etc/nginx/sites-available/api.office.lesailes.uz:6-8, 26-31`).

**Статику обязано отдавать то же имя — `api.office.lesailes.uz`.** Положишь на любой другой vhost
(`office.lesailes.uz` и прочие) — каждый запрос уйдёт на чужой хост, вернётся 404, и человек увидит
«Что-то пошло не так». Симптом не похож на причину: приложение грузится, стили на месте, ломается
только вход — и искать будут в авторизации, а не в nginx.

Отсюда же: URL в BotFather, `base` в `vite.config.ts` и `location` в nginx должны совпадать
буква в букву, включая хвостовой слэш.

## 2. Сборка

```
cd /home/davr/managers/passport_miniapp
/root/.bun/bin/bun install
/root/.bun/bin/bun --bun run build
```

- **`--bun` обязателен.** Дефолтный `node` на боксе — 16.17.0, Vite 7 его отвергает и падает с
  обманчивым `TypeError: crypto.getRandomValues is not a function`. Убрать флаг внутрь npm-скрипта
  нельзя: ни `bun`, ни `bunx` не лежат в PATH того шелла, который bun поднимает для скриптов.
  Альтернатива — собрать с `PATH=/root/.nvm/versions/node/v20.20.2/bin:$PATH`.
- `bun run build` = `tsc --noEmit && vite build`: тайпчек — часть сборки, и он же ловит непереведённую
  строку (словари типизированы как `Record<Lang, Dict>`).
- Ожидаемый результат: `dist/index.html` (~2.4 kB) + `dist/assets/index-*.js` (~12 kB) +
  `dist/assets/style-*.css` (~4.4 kB).
- **Проверить глазами:** в `dist/index.html` пути ассетов начинаются с `/passport-app/assets/`.
  Если нет — собралось с чужим `base`, и на проде будут 404 на ассеты.
- `dist/` в `.gitignore`: собирать на боксе, коммитить нечего.

## 3. nginx

Файл: `/etc/nginx/sites-available/api.office.lesailes.uz` (в `sites-enabled` — симлинк на него).
Сейчас в vhost есть только `location /` — блок статики станет первым и единственным исключением.

Форма скопирована с работающего соседа `/training-app/`
(`/etc/nginx/sites-enabled/api.lesailes.uz:67-72`), а не изобретена:

```
    # PASSPORT MINIAPP START #
    location ^~ /passport-app/ {
        alias /home/davr/managers/passport_miniapp/dist/;
        index index.html;
        try_files $uri $uri/ /passport-app/index.html;
        add_header Cache-Control "no-cache";
    }
    # PASSPORT MINIAPP END #
```

- Ставить внутрь `server { … listen 443 ssl … }`, **до** `location /`. `^~` даёт приоритет над
  префиксом `/`, иначе всё уедет в прокси.
- Хвостовые слэши в `location` и в `alias` — оба обязательны. `alias` без слэша склеивает путь неверно.
- `try_files` падает на **URI** (`/passport-app/index.html`), а не на файл: он повторно входит в эту же
  location и резолвится через `alias`. Это ровно та грабля, на которой стоял training-app.
- `Cache-Control: no-cache` — чтобы `index.html` не залипал у людей после следующей сборки. Ассеты
  хешированы в имени, их кэш безопасен и так.
- gzip в vhost уже включён и покрывает `application/javascript` и `text/css` (строки 14-21) — отдельно
  настраивать нечего: 12 kB JS уходит по проводу примерно за 5 kB.
- Права проверены: `www-data` проходит весь путь (каталоги 755, файлы 644) — `chmod` не нужен.
- Блоки, помеченные `# managed by Certbot`, не трогать.

### Порядок применения

```
cp /etc/nginx/sites-available/api.office.lesailes.uz \
   /etc/nginx/sites-available/api.office.lesailes.uz.bak.passport_app_$(date +%Y%m%d-%H%M%S)
# правка файла
nginx -t
systemctl reload nginx        # reload, НЕ restart
```

Имя бэкапа — в принятом здесь формате `<vhost>.bak.<повод>_<YYYYMMDD-HHMMSS>`
(ср. `clickapp.choparpizza.uz.bak.host_header_fix_20260522-102602`).

`nginx -t` до reload — не формальность: reload с битым конфигом оставит в памяти старый, и файл на
диске молча разойдётся с тем, что реально работает; следующий чужой reload уронит vhost.

### Проверка после reload

Колонка «до» снята вживую 2026-08-12, ещё без блока:

| проверка | до | ожидание после |
|---|---|---|
| `curl -o /dev/null -w '%{http_code}' https://api.office.lesailes.uz/` | `200` | `200` — API не задет |
| `.../passport-app/` | `404` | `200`, `Content-Type: text/html` |
| `.../passport-app/assets/<имя из dist>.js` | — | `200`, `application/javascript` |
| `.../passport-app/nosuchpath` | — | `200` (SPA-fallback отдаёт index.html) |
| `curl .../api/passport/tg/me` без заголовков | `401 {"error":"unauthorized"}` | тот же `401` — доказывает, что статика не перехватила API на том же origin |

Последняя строка — главная: она и есть проверка «остальные маршруты vhost живы», потому что весь API
этого хоста висит на одном `location /`.

### Откат

Если хоть одна строка таблицы не сошлась:

```
cp /etc/nginx/sites-available/api.office.lesailes.uz.bak.passport_app_<ts> \
   /etc/nginx/sites-available/api.office.lesailes.uz
nginx -t && systemctl reload nginx
```

и перепроверить `/` и `/api/passport/tg/me` — они должны вернуться к `200` и `401`.

## 5. Живой прогон — только человек с телефоном

Предусловия: ворота §0 закрыты, статика отдаётся, Mini App URL настроен.

1. **(Админ)** Оформить стажировку и напечатать лист с QR. Требует `passport.enrollments.manage`.
2. **(Телефон)** Сканировать QR **с бумаги**, не с экрана: печатный путь целиком ни разу не проверялся вживую.
3. Ожидать экран паспорта (после C2) либо плейсхолдер «Паспорт стажёра · Готовится».
4. **Погашение инвайта.** Тем же QR зайти со второго аккаунта → должно прийти «QR-код не для этого
   аккаунта» (`403 wrong_account`). Эта ветка не проверена **нигде**: ни живьём, ни тестом
   (`tg-controller.test.ts` — 47 строк, покрывает только `deadlineStatus`/`parseTimestamp`).
   Живой прогон — единственная возможность её доказать; не пропускать.
5. **Язык.** Биндинг с `lang='uz'` на телефоне без прежнего выбора → узбекский текст **и** подсвеченная
   «Oʻz» (до фикса `7ac6305` подсветка врала).
6. **Протухание сессии.** Оставить мини-апп открытым дольше 12 ч либо погасить сессию в Redis, затем
   сделать действие: должна пройти молчаливая пере-авторизация (ровно одна попытка). Экран «Вход устарел»
   правомерен только если и повтор не прошёл. Его единственное лекарство — «закройте и откройте заново»,
   и это опирается на допущение, что Telegram при перезапуске выдаёт свежий `initData` с новым
   `auth_date`. Проверить отсюда нельзя — **подтвердить именно на этом шаге**.
7. **Плохая сеть.** Включить и выключить авиарежим на экране паспорта: ожидается «Нет связи» с кнопкой
   «Повторить», а не бесконечный скелетон.
8. **Темы и квиз** — только после C3.

## Добавление в спеку C5 (из фикс-раунда C1, 2026-08-12)

`defer` не убирает ожидание. Отложенный классический скрипт и модуль делят одну очередь исполнения в порядке документа, поэтому при недоступном `telegram.org` наш `main.ts` не запускается до самого таймаута браузера — в замере это около 30 секунд. Фикс C1 сделал эти секунды объяснёнными (подсказка «Связь медленная» лежит статикой в разметке и открывается CSS-задержкой, независимо от того, выполнился ли наш JS), но не сократил их.

**Чистое решение — раздавать `telegram-web-app.js` со своего origin.** Это убивает весь класс отказов: скрипт приезжает с того же `api.office.lesailes.uz`, что и приложение с API, и внешняя блокировка перестаёт влиять. Решение меняет то, что раздаёт nginx, поэтому принадлежит C5, а не C1.

Если делать: положить файл рядом со сборкой, заменить `src` в `index.html` на относительный путь, и не забыть, что версия SDK теперь фиксируется вручную — обновлять придётся осознанно, что для пилота скорее плюс.

**CSP:** на `api.office.lesailes.uz` её сегодня нет, и спека C5 не добавляет. Если появится — inline-скрипт в `<head>` потребует `'unsafe-inline'`; при блокировке страница деградирует до русской строки, а не в пустоту.
