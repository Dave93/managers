# KPI — План 3: загрузка Workly и автопункт «Приход и уход»

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HR загружает выгрузку посещаемости Workly (xlsx, xls или csv), сопоставляет колонки и пишет месяц в `kpi_attendance`. Форма оценки предлагает балл пункта «Приход и уход». HR правит табельный номер сотрудника.

**Architecture:** Импорт в два шага. `parse` кладёт файл в Redis на 30 минут и отдаёт листы с первыми 20 строками. `commit` читает файл заново, разбирает строки по выбранным колонкам и в одной транзакции заменяет прошлый импорт месяца. Разбор файла, ячеек и сопоставление — чистые функции в `attendance-parse.ts` с `bun test`, без базы. Предложение для оценки строится в `reviews.ts`: черновик и новая форма считают его по живым данным, отправленная оценка показывает снимок из `kpi_review_items.auto_value`. В админке новый экран `/kpi/attendance` и правка табельного номера во вкладке «Сотрудники».

**Tech Stack:** Bun 1.4, Elysia 1.4, Drizzle ORM 0.44 / drizzle-kit 0.31, PostgreSQL, ioredis, SheetJS `xlsx` 0.18.5, bun:test; админка Next.js 15, React 19, TanStack Query 5, shadcn/ui, sonner.

Предыдущие планы: `docs/superpowers/plans/2026-10-25-kpi-1-backend-core.md` (соглашения backend, `KpiError`/`run`, `actorFrom`, фикстуры) и `docs/superpowers/plans/2026-10-25-kpi-2-admin.md` (клиент `admin/lib/kpi-api.ts`, `admin/lib/kpi/*`, `ScreenGate`, группа меню, вкладка «Сотрудники»). ## Решения плана

Спека их не задаёт. Каждое помечается в `docs/superpowers/kpi-handoff.md` как «наше решение».

1. Колонки выбираются по номеру (0 — колонка A), а не по тексту заголовка: заголовки бывают пустыми и повторяются. Одна колонка может закрывать несколько полей, например «Приход» с датой и временем даёт и дату, и приход.
2. Табельный номер берётся из текстового вида ячейки, как его видит HR в Excel: число `123` с форматом `00000` даёт `00123`.
3. Две строки одного сотрудника за один день: действует первая, остальные уходят в отчёт с причиной `duplicate_day`.
4. Если не сопоставилась ни одна строка, импорт не пишется (422 `nothing_matched`), прошлый импорт месяца остаётся действующим. Ошибка в колонках не стирает хорошие данные.
5. Импорт в закрытый месяц запрещён (409 `period_closed`).
6. Уход раньше прихода при времени без даты означает ночную смену: к уходу прибавляются сутки.
7. Опоздание принимает целые минуты, «Ч:ММ» и долю суток Excel (ячейка в формате времени). Пусто — 0.
8. CSV читается как UTF-8, а если байты не UTF-8, как windows-1251. Разделитель угадывает SheetJS. Файл `.xlsx` должен начинаться с `PK\x03\x04`, `.xls` — с `D0 CF 11 E0` или с `<` (HTML-таблица, которую Excel открывает как xls). Иначе 422 `bad_file`.
9. Файл в Redis привязан к загрузившему: чужой токен даёт тот же ответ, что истёкший (404 `upload_expired`).
10. Отправленная оценка хранит снимок предложения в `kpi_review_items.auto_value` и показывает его, даже если Workly потом перезагрузили. Живые данные видят только черновик и новая форма.
11. Заметка к пункту проверяется по всем пунктам сохраняемой оценки, а не только по присланным в теле. Иначе черновик, сохранённый до импорта с другим баллом, уходил бы на отправку `{}` без заметки.

Правила, которые сигнатуры не задают:
- `readGrids`. Проверка сигнатуры по пункту 8 «Решений». CSV: `new TextDecoder("utf-8", { fatal: true })`, при исключении `new TextDecoder("windows-1251")` (Bun его поддерживает, проверено). Ведущий `\ufeff` срезается, затем `XLSX.read(text, { type: "string", raw: true })`. xlsx и xls: `XLSX.read(bytes, { type: "array", raw: true, cellDates: false })`; исключение → `bad_file`. Для каждого листа с `!ref` диапазон берётся от A1: `range = encode_range({ s: { r: 0, c: 0 }, e: decode_range(ws["!ref"]).e })`. Затем `raw = sheet_to_json(ws, { header: 1, raw: true, defval: null, blankrows: true, range })` и `text` — то же с `raw: false, defval: ""`. Лист, где все `text` после `trim` пустые, пропускается.
- `previewOf`. Ширина — самая длинная строка `text`. `headers` = строка `header_row`, `rows` = первые 20 строк `text`; обе дополняются `""` до ширины. `total_rows` = `text.length`.
- `parseDay`. Число ≥ 1 — серийная дата Excel, дробная часть отбрасывается (`XLSX.SSF.parse_date_code`). Строка после `trim`: `Д.М.ГГГГ` или `ДД.ММ.ГГГГ`, либо `ГГГГ-ММ-ДД`, за каждой может идти время через пробел или `T`. Несуществующая дата (31.02) → `null`. Остальное → `null`.
- `parseTime`. Пусто → `null`. Число `0 ≤ v < 1` означает долю суток к `day`. Число ≥ 1 считается серийной датой со временем, и дата берётся из ячейки. Строка `Ч:ММ` или `Ч:ММ:СС` даёт время к `day`, строка с датой и временем несёт свою дату. Часы 0..23, минуты и секунды 0..59. Результат: `new Date(Date.UTC(y, m - 1, d, H - 5, M, S)).toISOString()`. Иначе `"bad"`.
- `parseLate`. Пусто → 0. Целое число ≥ 0 → оно. Число в `(0, 1)` → `Math.round(v × 1440)`. Строка из цифр → число. Строка `Ч:ММ[:СС]` → `Ч × 60 + ММ`. Остальное, в том числе отрицательное и дробное ≥ 1, → `"bad"`.
- `parseAbsent`. `true` (булева ячейка), число 1 и строки (после `trim`, без учёта регистра) `1`, `да`, `yes`, `true`, `+`, `прогул` → `true`. Остальное → `false`.
- `validateMapping`. Объект; ключи только из `AttendanceField`; `external_id` и `date` обязательны; значения — целые `0 ≤ v < width`; `null` и `undefined` у необязательных выбрасываются. Одинаковые номера у разных полей допустимы. Иначе `null`.
- `parseRows`. Строки после `headerRow`. Строка, где все `text` после `trim` пустые, пропускается и в `total` не входит. Причины по порядку проверки:
  1. `text` колонки номера после `trim` пуст → `no_external_id` (`external_id: null`);
  2. `parseDay` дал `null` → `bad_date`;
  3. день вне `[period, addMonths(period, 1))` → `outside_period`;
  4. приход или уход `"bad"` → `bad_time`;
  5. опоздание `"bad"` → `bad_late`.

  Колонки нет в сопоставлении: опоздание 0, прогул `false`, приход и уход `null`. Если уход пришёл временем без даты (число `< 1` или строка `Ч:ММ[:СС]`) и он раньше прихода, к нему прибавляются сутки.
- `matchRows`. Номера сотрудников сравниваются после `trim`, с учётом регистра. Сотрудников с номером нет → `unknown_external_id`, больше одного → `ambiguous_external_id`. Пара `(employee_id, day)` уже занята более ранней строкой → `duplicate_day`.
- `attendanceSuggestion`. Пусто → `null`. `days` = число строк, `absent` = прогулы, `ontime` = присутствие с `late_minutes === 0`, `late` = присутствие с опозданием, `score = Math.round(100 × ontime / days)`. Основание: `` `Workly: ${days} ${слово}, вовремя ${ontime}, опозданий ${late}, прогулов ${absent}` ``. `слово` — «день», «дня» или «дней» по обычному правилу (1, 21 → день; 2–4, 22 → дня; 0, 5–20, 11–14 → дней).

Правила `parseUpload` (по порядку):
1. Не `File` → 422 `file_required`. `fileKind(name)` пуст → 422 `bad_file_type`. `size > MAX_UPLOAD_BYTES` → 422 `file_too_large`.

Правила `commitImport` (по порядку):
1. Токен не строка, ключа нет или `user_id` чужой → 404 `upload_expired`.
2. `parsePeriod(body.period)` → 422 `bad_period`.
3. Лист с именем `body.sheet` → иначе 422 `bad_sheet`.
4. `header_row`: нет → `guessHeaderRow(grid.text)`; иначе целое 1..20 и не больше числа строк листа, иначе 422 `bad_header_row`.
5. `validateMapping(body.mapping, ширина листа)` → `null` → 422 `bad_mapping`.
6. `parseRows`, затем транзакция:
   - `select pg_advisory_xact_lock(hashtext('kpi_attendance:' || :period))`;
   - `isPeriodClosed` → 409 `period_closed`;
   - активные сотрудники с `external_id is not null` → `matchRows`;
   - `days` пуст → 422 `nothing_matched` с `{ rows_total, unmatched }`, где `unmatched` — первые 20 причин по возрастанию `row`: HR должен увидеть, почему не сошлось;

   - вставка строки импорта, затем `days` пачками по 1000 с `onConflictDoUpdate` по `(employee_id, day)` (все поля, включая `import_id`).
7. `unmatched` = причины `parseRows` и `matchRows`, по возрастанию `row`, в базу и ответ идут первые `UNMATCHED_LIMIT`. Счётчики: `rows_matched = days.length`, `rows_unmatched` — полное число причин, `rows_total = rows_matched + rows_unmatched`.
8. Токен после успешного `commit` не удаляется: HR может перезалить тот же файл с другими колонками за 30 минут.
