# Оборотно-сальдовая ведомость склада — Design Doc

Дата: 2026-10-14. Статус: дизайн одобрен в чате по разделам, пользователь попросил сразу писать план и реализовывать.

Продолжение `2026-10-08-inventory-interim-and-stock-design.md` (книжное количество, «Остатки склада»). Опирается на правило возврата пересчёта (`branchMayReopen`, спека сверки §13).

## 1. Цель

Аналог «Оборотно-сальдовой ведомости» iikoOffice за **календарный месяц**: по складу и товару — остаток на начало, обороты по видам проводок, остаток на конец; в количестве и (только офису) в суммах по себестоимости. Плюс сводная по всем складам в суммах.

## 2. Решения

| # | Вопрос | Решение |
|---|---|---|
| 1 | Для кого | Офис (`inventory.templates`) — все склады, количество и суммы, сводная. Филиал (`inventory.count`, склады из `users_stores`) — свои склады, **только количество**, без сводной |
| 2 | Суммы | Исключение из правила «сумм нет нигде» (спека 2026-10-08, §1): суммы видит только офис; филиалу они не отдаются в API |
| 3 | Период | Календарный месяц. Начало — 1-е 00:00; конец — 1-е следующего месяца 00:00 (после документа инвентаризации в 23:59) |
| 4 | Инвентаризация | Отдельная колонка оборота «Инвентаризация ±» (`INVENTORY_CORRECTION`); конец месяца = факт = начало следующего |
| 5 | Какие месяцы видит филиал | Текущий — никогда. Любой прошедший — закрыт, пока у склада есть месячный пересчёт за этот месяц в черновике или отправленный, который филиал ещё может вернуть (`branchMayReopen`): вернуть и править можно и старые месяцы, срок ограничен только при создании. Прошлый месяц закрыт ещё и без инвентаризации вовсе — нет ни пересчёта в админке, ни проведённого документа инвентаризации iiko (`inventory_reconciliations.iiko_doc_state = posted`): тогда «Конец» — учётный остаток, а за дни прошлого месяца разрешён промежуточный. **Изменено 14.10.2026:** было «прошлый — только с пересчётом в админке»; в сентябре 2026 пересчёт в админке был у 3 складов, документ iiko проведён у 54 |
| 6 | Сводная | Строки — склады, колонки — обороты **в суммах**, только офис. Количество разных товаров не складываем |
| 7 | Экран | Один экран: фильтры «Месяц» и «Склад». «Все склады» — сводная; выбран склад — ведомость по товарам. Клик по строке сводной ставит склад в фильтр. Фильтры в URL (`nuqs`) |
| 8 | Источник данных | Снимок в БД, заполняется BullMQ-задачей; экран iiko не трогает |
| 9 | Текущий месяц | «По вчера включительно»: конец — сегодня 00:00, OLAP по вчера. 1-го числа данных за текущий месяц нет |
| 10 | Обновление | Ночью 03:00 (Ташкент) — текущий и прошлый месяц, все склады. Более старые — только кнопкой офиса |
| 11 | Хранение | Бессрочное, очистки нет. После отбрасывания пустых проводок (§5) — ~8 МБ/мес: сентябрь 2026 — 32 382 строки оборотов и 13 513 остатков (замер 14.10.2026); на проде свободно 271 ГБ |

## 3. Что известно об iiko (проверено 14.10.2026, только чтение)

- `GET v2/reports/balance/stores?timestamp` **без `store`** отдаёт все склады: 10 790 строк, 67 складов, ~0,5 с. Поля: `store`, `product`, `amount`, `sum`.
- OLAP `TRANSACTIONS`, фильтр `Account.Type = INVENTORY_ASSETS` (или `Account.Id = склад`), группировка `Account.Id × Product.Id × TransactionType`, агрегаты `Amount.In`, `Amount.Out`, `Sum.Incoming`, `Sum.Outgoing`. По всем складам за месяц — 67 940 строк, **~100 с**; по одному складу ~4 с.
- Тождество **начало(1-е 00:00) + Σ(In − Out) по всем типам = конец(1-е след. 00:00)** за сентябрь 2026 сошлось для **47 817 из 47 817** пар склад × товар — и в количестве, и в суммах.
- Типы проводок на складах за сентябрь 2026: `INVOICE`, `SESSION_WRITEOFF`, `TRANSFER`, `WRITEOFF`, `INVENTORY_CORRECTION`, `OUTGOING_INVOICE`, `RETURNED_INVOICE`, `TRANSFORMATION`, `PRODUCTION`, `STORE_COST_CORRECTION` (количество 0, только сумма).
- `StartBalance.*`/`FinalBalance.*` из OLAP не использовать (спека 2026-10-08, §3).

## 4. Колонки

Порядок фиксирован. «Всегда» — колонка есть даже при нулях; «если не ноль» — только когда в выдаче есть ненулевое значение.

| Ключ | Подпись | Типы iiko | Значение | Показ |
|---|---|---|---|---|
| `start` | Начало | `balance/stores` на 1-е 00:00 | остаток | всегда |
| `invoice` | Приход (накладные) | `INVOICE` | In − Out | всегда |
| `sales` | Реализация | `SESSION_WRITEOFF` | Out − In | всегда |
| `transfer` | Перемещения ± | `TRANSFER` | In − Out; в ответе также `in`, `out` | всегда |
| `writeoff` | Списания | `WRITEOFF` | Out − In | всегда |
| `inventory` | Инвентаризация ± | `INVENTORY_CORRECTION` | In − Out | всегда |
| `outgoing_invoice` | Расходные накладные | `OUTGOING_INVOICE` | Out − In | если не ноль |
| `returned_invoice` | Возврат поставщику | `RETURNED_INVOICE` | Out − In | если не ноль |
| `transformation` | Переработка ± | `TRANSFORMATION` | In − Out | если не ноль |
| `production` | Приготовление ± | `PRODUCTION` | In − Out | если не ноль |
| `cost_correction` | Корректировка себестоимости | `STORE_COST_CORRECTION` | In − Out (только сумма) | только в суммах, если не ноль |
| `other` | Прочее ± | любой другой тип | In − Out | если не ноль |
| `end` | Конец | `balance/stores` на конец | остаток | всегда |

Расходные колонки (`sales`, `writeoff`, `outgoing_invoice`, `returned_invoice`) показываются положительным числом расхода; «±»-колонки — со знаком (+ приход, − расход). Тождество: `start + invoice − sales + transfer − writeoff + inventory − outgoing_invoice − returned_invoice + transformation + production + cost_correction + other = end`.

## 5. Данные

Внешних ключей на `corporation_store`/номенклатуру нет (как у `inventory_counts`). `period` — последний день месяца (как `inventory_counts.period`).

### `inventory_turnover` — обороты
PK (`period`, `store_id`, `product_id`, `tx_type`).

| Колонка | Тип |
|---|---|
| `period` | date |
| `store_id`, `product_id` | uuid |
| `tx_type` | varchar(40) |
| `qty_in`, `qty_out` | numeric(14,4) |
| `sum_in`, `sum_out` | numeric(18,4) |

### `inventory_turnover_balance` — остатки
PK (`period`, `store_id`, `product_id`).

| Колонка | Тип | Примечание |
|---|---|---|
| `start_qty`, `end_qty` | numeric(14,4) | |
| `start_sum`, `end_sum` | numeric(18,4) | |
| `consistent` | boolean | тождество: количество ±0,0005 и сумма ±1 |

Проводки, где количество и сумма прихода и расхода нулевые, не пишутся: документ инвентаризации iiko перечисляет все товары, в том числе с нулевой разницей, и такие строки — больше половины месяца (сентябрь 2026: 35 559 из 67 941). Строка остатков пишется для товара с ненулевым началом, концом или ненулевым движением.

### `inventory_turnover_fetch` — когда снят снимок
PK (`period`, `store_id`).

| Колонка | Тип | Примечание |
|---|---|---|
| `fetched_at` | timestamptz | «загружено …» |
| `data_through` | date | последний день, вошедший в снимок (закрытый месяц — `period`; текущий — вчера) |

Состояние загрузки (очередь, «12 / 67», ошибки) — в Redis, как у сверки.

## 6. Получение снимка

- Очередь BullMQ `inventory_turnover` (`INVENTORY_TURNOVER_QUEUE`), третий `Worker` в `cron/inventory_reconcile_worker.ts`: concurrency 1, один токен iiko на задачу (`withIikoClient`, `logout` в `finally`). Очередь входит в проверку `worker-health` («Обработчик не запущен»).
- Данные задачи `{ period, storeId | null, statusKey }`; `jobId = turnover-<period>` / `turnover-<period>-<storeId>`.
- Границы: `from` = 1-е число месяца; `to` (включительно) = `period` для закрытого месяца или вчера для текущего; конец = `to + 1 день` 00:00. Если `to < from` (1-е число текущего месяца) — задача ничего не грузит, снимок месяца пуст.
- **Все склады:** `balance/stores` без `store` на начало и на конец; склады = из балансов ∪ `corporation_store`; затем по складу — OLAP `TRANSACTIONS` (`Account.Id = склад`, все типы), запись склада одной транзакцией (удалить снимок склада за месяц → вставить обороты, остатки, `fetch`). Прогресс `done/total` в Redis. Ошибка на складе (после повторов клиента) — склад в `failed`, прежний снимок остаётся, задача идёт дальше. Склад без остатков и без движения — снимок удаляется, `fetch` пишется (данные «пусто» актуальны).
- **Один склад:** то же для одного склада (`balance/stores?store=`).
- Повторная постановка, пока идёт загрузка месяца (или этого склада, или месяца при загрузке склада) — 409 `already_running`.
- Расписание (`cron/src/index.ts`, `Asia/Tashkent`): `0 3 * * *` — текущий и прошлый месяц, все склады.

## 7. API

Плагин `turnoverRoutes` подключается в `inventoryControllerImpl`.

| Маршрут | Право | Что делает |
|---|---|---|
| `GET /inventory/turnover/periods?store_id` | `inventory.count` | Месяцы с 2026-01 по текущий (новые сверху): `period`, `open`, `reason` (`current` / `not_fixed` / null), `data_through`, `fetched_at`. Офис — без `store_id`: открыты все; филиал — `store_id` обязателен и свой |
| `GET /inventory/turnover/summary?period` | `inventory.templates` | Строки-склады в суммах по колонкам §4, итог, `columns`, `fetched_at`/`data_through` по складу, `inconsistent` (число строк), статус загрузки |
| `GET /inventory/turnover?period&store_id` | `inventory.count` + доступ к складу | Ведомость склада: `columns`, строки товаров (`code`, `name`, `unit_name`, `group_name`, `qty` по колонкам, `sum` по колонкам — **только офису**, `consistent`). Филиал: свой склад и открытый месяц, иначе 403 |
| `POST /inventory/turnover/refresh` `{period, store_id?}` | `inventory.reconcile` | Ставит задачу; 409 при идущей загрузке; 422 — некорректный или будущий месяц |
| `GET /inventory/turnover/status?period` | `inventory.templates` | Статус загрузки месяца и отдельных складов |

`columns` строит сервер: только видимые колонки в порядке §4 (ведомость филиала — без `cost_correction`).

## 8. Экран

`/<locale>/inventory/turnover`, меню «Инвентаризация» → «Оборотная ведомость» (`inventory.count`).

- Фильтры: «Месяц» (по умолчанию прошлый; закрытые филиалу — неактивны с подсказкой «откроется после фиксации пересчёта» / «текущий месяц недоступен»), «Склад» (офис — «Все склады» + все; филиал — свои, один — выбран сразу). URL: `?period=2026-09-30&store=<uuid>`.
- Строка состояния: «Данные по 13.10 включительно · загружено 14.10 03:05»; у офиса «↻ Обновить из iiko» и прогресс «12 / 67»; предупреждение «Обработчик не запущен».
- «Все склады» (офис): таблица складов в суммах + «Итого»; ↻ в строке склада; клик — выбор склада.
- Склад: поиск, группы, переключатель «Количество / Сумма» (офис); строки, у которых в текущем режиме одни нули, не показываются (филиалу они и не отдаются), таблица «Код / Товар / Ед.» + колонки; «не сходится» — пометка строки; «Перемещения ±» — подсказка с приходом и расходом.
- Числа: «+» зелёным, «−» красным в «±»-колонках (как разница в инвентаризации).

## 9. Проверки

- Юнит (`turnover/pure.test.ts`): раскладка типов по колонкам (неизвестный → `other`; доп. колонки только если не ноль; `cost_correction` только в суммах), тождество и `consistent`, границы периода (закрытый, текущий «по вчера», 1-е число — пусто, будущий — ошибка), доступность месяца филиалу (текущий; прошлый без пересчёта и без документа iiko; прошлый с документом iiko; старый с черновиком месячного; старый без пересчётов).
- HTTP (`turnover/routes.test.ts`, `bun run test:http:turnover`): у филиала нет сумм; чужой склад / текущий месяц / прошлый без фиксации / старый с черновиком месячного / сводная — 403; `refresh` филиала — 403; повторный `refresh` — 409; офис — 200 с суммами.
- Сквозная на iiko (только чтение): сентябрь 2026, все склады — тождество во всех строках; несколько товаров склада 21027 сверить с ОСВ iikoOffice (вручную, пользователь).

## 10. Не входит

Выгрузка в Excel; разбивка по дням внутри месяца; ведомость по товарам по всем складам сразу; ОСВ по денежным счетам.
