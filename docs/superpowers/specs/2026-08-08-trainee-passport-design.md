# Паспорт стажёра — Design Doc

Дата: 2026-08-08. Статус: одобрен по секциям, ждёт финального ревью спеки.
Контекст-ресёрч: документы HR (7 шт.), IT-аудит (managers/office, les-training), мировые практики QSR (McDonald's SOC/FSOC, TWI, Starbucks, KFC). Концепт-артефакт: https://claude.ai/code/artifact/ad514b4a-5d1f-4b01-aa92-98e6955408f3

## 1. Проблема и цель

Стажёры всех позиций обучаются в филиале наставниками-практиками. Куррикулум размазан по департаментам (9 отделов в «стажировка варакаси»), наставники забывают темы или не знают их, прогресс непрозрачен, фиксация бумажная. Цель: цифровой «паспорт стажёра» — структурированный путь обучения с прозрачным прогрессом, честными проверками и привязкой к испытательному сроку и надбавкам.

## 2. Зафиксированные решения заказчика

## 3. Выбранный подход (A из трёх)

Модуль `passport` внутри монорепо `/home/davr/managers` («office»): office_api (Elysia + Drizzle + Postgres `managers`), office_admin (Next.js, office.lesailes.uz), office_cron. Переиспользуем: attestation-движок (банк вопросов, grading, киоск+PIN, valid_months, аналитика), реестр `employees` (386, terminal-scoped), RBAC, деплой. Из les-training берём паттерн TG-miniapp (initData HMAC, QR-инвайт) и X-Accel-доставку видео (на api.office.lesailes.uz).

Отклонены: B (отдельный сервис — дублирование auth/RBAC/реестра), C (расширение les-training — les-only, живёт внутри order-receiver, нет RBAC).

## 4. Модель данных (Postgres `managers`, префикс `passport_`)

Куррикулум:
- `passport_programs` — на позицию (8 шт.): position, title_ru, title_uz, active.
- `passport_modules` — блок владельца: title_ru/uz, brand (null|chopar|les), owner_department, status (draft→review→published, версионируется), exam_test_id → attestation_tests. Кухонные СТАНЦИИ повара = отдельные модули (brand=chopar: тесто, снеки, заготовка, оборудование; brand=les: снеки, Лестер, мясо, заготовка, оборудование) — каждая сертифицируется своим экзаменом, «надбавка за станцию» = штамп модуля-станции, «универсал бренда» = все станции бренда закрыты.
- `passport_program_modules` — module↔program: sort, required, deadline_days.
- `passport_topics` — тема: title_ru/uz, TWI (step/key_point/reason ×2 языка), video_id→passport_media, verification_type (quiz | observation | quiz+observation | +photo | dual), quiz_test_id → attestation_tests, observation_checklist jsonb (пункты + обязательные устные вопросы, двуязычные).

Стажировка:
- `passport_enrollments` — employee_id, program_id, started_at, probation_deadline, status (active/completed/failed/paused), версия куррикулума.
- `passport_tg_bindings` — telegram_id↔employee (одноразовый QR-инвайт); у менеджеров/аудиторов binding к office-user.
- `passport_topic_progress` — проекция: level 0–4, quiz_attempt_id, observed_by, observation_answers jsonb, photo_path, recheck_due_at.
- `passport_signoffs` — append-only журнал всех событий (material_opened, quiz_passed, observed, recheck_passed/failed, level_set/rolled_back, stamp_issued): actor, terminal, ip/subnet, created_at. Источник аудита и детектора.
- `passport_stamps` — module_cert (valid_until), universal_chopar, universal_les, probation_passed; выгрузка для зарплаты читает ТОЛЬКО отсюда.

Честность:
- `passport_qr_tokens` — nonce, enrollment+topic, TTL 60 c, single-use.
- `passport_rechecks` — назначение (random|manual), assigned_to, due_at (7 дней), result.
- `passport_flags` — тип, subject, meta, resolved.

Медиа: `passport_media` (file_path, status, transcode_error) + nginx X-Accel internal location; транскод — реюз les-transcode-worker.

Attestation-движок: в `attestation_test_attempts` добавляется `source` (kiosk|miniapp); киоск-флоу не меняется.

## 5. API и роли

Модуль `backend/src/modules/passport/` (конвенция: controller.ts + регистрация в controllers.ts). Группы:

1. Конструктор (cookie-auth + RBAC): CRUD программ/модулей/тем. `passport.curriculum.edit` — департамент-скоуп (у office-user появляется поле department; редактор видит только свои модули; бренд-шефы = редакторы «кухни» своего бренда). `passport.curriculum.publish` — только HR.
2. Miniapp стажёра (TG initData HMAC → Redis-сессия): GET /passport/me; GET /passport/topics/:id (язык RU/UZ); POST /passport/quiz/:topicId/start|submit (source=miniapp, 2 провала подряд → пауза 1 ч); POST /passport/observation-qr.
3. Miniapp наставника (binding к office-user с `passport.signoff`, терминал-скоуп): скан QR → чек-лист → POST signoff (поштучные отметки, отказ тоже журналируется); GET mentor/queue.
4. Киоск/аудит: экзамен модуля = существующий attestation-киоск (PIN стажёра + PIN менеджера) → автоштамп; GET/POST rechecks (`passport.recheck`); GET dashboard/matrix, flags.

Права: passport.curriculum.edit / curriculum.publish / signoff / recheck / matrix.view / integrity / enrollments.manage / level4.grant.

Фон (office_cron): еженедельный генератор ре-проверок; детектор аномалий; бот-напоминания (новый бот на оба бренда, он же хостит miniapp): стажёру — тема дня/дедлайн, менеджеру — очередь, аудитору — ре-проверки.

## 6. Miniapp (один на оба бренда, форк les_training_miniapp: vanilla TS + Vite, статика /passport-app/)

Режим стажёра: Паспорт (прогресс-кольцо, дедлайн-полоса зелёный/жёлтый/просрочен, модули, штампы; переключатель RU/UZ, запоминается) → Модуль (темы, замки préreq, «экзамен на киоске») → Тема (видео → TWI-карточка → квиз → «Позвать наставника») → QR-экран (60 сек).
Режим наставника: Очередь (горящие дедлайны сверху) → Скан QR камерой → чек-лист с toggle по каждому пункту и вопросу → «Подписать · уровень N»; Мои стажёры.
UX: мобайл-first, короткие тексты, крупные тач-цели, устойчивость к плохой сети, хаптика.

ПРОЦЕСС UI (требование заказчика): перед вёрсткой — референсы на dribbble через chrome-attach; реализация через ui/taste-скиллы (aesthetic, design-taste-frontend, high-end-visual-design, frontend-design, motion-design).

## 7. Office-админка: 4 страницы

1. `/passport/curriculum` — дерево программа→модули→темы, drag-sort; двуязычные столбцы бок-о-бок; публикация заблокирована без обоих языков; статусы draft→review→published; изменения после публикации = новая версия (идущие стажировки остаются на своей, HR мигрирует вручную); редактор чек-листов наблюдения; переход в редактор вопросов аттестации.
2. `/passport/matrix` — филиал → стажёры × модули, цвет=уровень, красное=просрочка; фильтры бренд/филиал/позиция/наставник; клик → журнал; экспорт xlsx.
3. `/passport/integrity` — флаги; ре-проверки (назначенные/просроченные/провалы); рейтинг наставников (% провалов ре-проверок выпускников → KPI); audit-log конструктора; ручное назначение ре-проверки.
4. `/passport/enrollments` — запуск стажировки (employee + программа → QR-инвайт), карточка стажёра (таймлайн, штампы, продлить/завершить/прервать), выдача универсал-штампов (авто; ручной — только HR, с комментарием, светится в ленте).

## 8. Гейты и стейт-машина

- 0→1 «увидел»: открытие материала (журналируется).
- 1→2 «сделал»: квиз темы в miniapp; без квиза — сразу к наблюдению.
- 2→3 «сам»: QR-рукопожатие (TTL 60с, single-use, право на терминал) + ВСЕ пункты и КАЖДЫЙ устный вопрос «сдал»; «+фото» — снимок только с камеры, серверный timestamp; «двойная» — плюс асинхронная вторая подпись эксперта.
- 3→2 откат: провал ре-проверки; повторное наблюдение; флаг наставнику.
- 4 «учит»: вручную HR/бренд-шеф после практэкзамена (level4.grant). На старте — старшие повара и менеджеры.
- Модуль закрыт = все темы ≥3 И экзамен на киоске. Штамп с valid_until; истёк → пересдача экзамена (темы не сбрасываются).
- Универсал: все кухонные модули бренда → авто-штамп.
- Дедлайны: ок / ≤3 дня жёлтый / просрочен → пуш менеджеру; +3 дня → красное у HR + флаг. Двигает только HR.

## 9. Анти-фрод (полный список)

Закрыто конструкцией: массовое протыкивание (QR-рукопожатие + burst-детектор >5 подписей/10 мин + случайные ре-проверки + рейтинг наставника); сдача квизов другом (финалы на киоске под 2 PIN); квиз до материала (флаг); подписи вне 23:00–09:00 (флаг); квиз-спидран <5 c/вопрос (флаг); брутфорс (пауза 1 ч); предсказуемость проверок (случайная выборка 10% подписанного за 30 дней, min 1/филиал, срок 7 дней, кухня→бренд-шеф, прочее→аудитор/BRM); утечка PIN (ротация — уже в системе); чужой инвайт (одноразовость + unique binding); «универсал» сменой позиции (штампы от модулей).

Дополнительно:
1. Пересланный QR: скан только камерой miniapp наставника; журнал пишет IP/подсети обеих сторон (разные сети = сигнал); сверка подписи с графиком смен менеджера (work_schedules) — подпись в выходной = флаг.
2. Диктовка экзамена на киоске: киоск в зоне видеокамеры (регламент); журнал терминал+время → выборочная сверка с записью при ре-проверках.
3. Порча куррикулума изнутри: изменение опубликованного теста/чек-листа — только новая версия через HR; audit-log конструктора в ленте честности.
4. Старые фото: только камера, без галереи, серверный timestamp, EXIF не доверяем.
5. Надбавки мимо системы: зарплатная выгрузка читает только passport_stamps; ручной штамп — с комментарием и в ленте.

Остаточный риск: тотальный сговор менеджер+стажёр — экономически подавляется (ре-проверки другим человеком, KPI-последствия, камерная сверка), полностью не устраним.

## 10. Тестирование

- Юнит (bun test): стейт-машина уровней (чистые функции), QR-токены, правила детектора на фикстурах журнала, генератор ре-проверок (детерминированный rng), валидация «оба языка».
- Интеграция: права-скоупы (чужой модуль, чужой терминал, miniapp≠kiosk source).
- E2E-скрипт: инвайт → квиз → подпись → экзамен → штамп, локальный стенд перед релизом.
- Пилот: 2–3 двухбрендовых филиала; выход: 5–10 стажёров прошли модуль целиком, менеджеры работают без сопровождения.

## 11. Деплой и пререквизиты

Рельсы managers: drizzle-миграции → office_api (pm2) → office_admin (build) → miniapp статика nginx → office_cron.
ПРЕРЕКВИЗИТ №0: у Postgres `managers` нет бэкапов; до пилота — ночной pg_dump с ротацией (паспорт = зарплатно-значимые данные).

## 12. Этапы

1. Ядро: миграции, конструктор, enrollments+инвайты, miniapp стажёра (материалы+квизы), простая подпись (без QR). Параллельно контент-спринт HR (перенос «варакаси», добивка пустых листов, оба языка). Старт пилота.
2. Гейты: QR-рукопожатие, обязательные вопросы, киоск-экзамены, фото-темы, штампы универсалов.
3. Прозрачность: матрица, лента честности, детектор, генератор ре-проверок, рейтинг наставников.
4. Деньги: зарплатная выгрузка из штампов, KPI наставничества, ворота испытательного (совместно с HR-политикой).
